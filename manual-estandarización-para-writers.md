# Manual de Estandarización para Writers

## Descripción

Este manual está dirigido a los Writers y tiene como objetivo definir las normas de estandarización que deben seguirse para la implementación de futuros feats (funcionalidades o contenidos) dentro del repositorio de documentación. Estas normas buscan mantener la claridad, organización y coherencia en todo el contenido desarrollado.

---

## Tomar en cuenta:

- **Claridad:** El contenido debe ser comprensible y bien estructurado.
- **Estandarización de carpetas:** Cumplimiento de la convención de nombres.
- **Estandarización de archivos:** Uso correcto del formato establecido.
- **Implementación de cambios:** Comprensión y aplicación correcta del proceso para nuevos contenidos.

---

## Estandarización para Carpetas

- **Nombre en minúsculas**
- **Espacios reemplazados por guiones (-)**

### Ejemplo:

✅ `guías-técnicas`  
✅ `acerca-de-isc-projects`  
✅ `manuales`

---

## Estandarización para Nombres de Archivos

- **Usar minúsculas**
- **Reemplazar espacios por guiones (-)**
- **Utilizar extensiones estándar (.md para Markdown)**

### Ejemplo:

✅ `tareas-por-rol.md`  
✅ `tipos-de-roles.md`

---

### ¿Dónde implementar nuevos cambios?

Antes de crear una carpeta nueva, asegúrate de que el contenido que vas a generar no pertenezca ya a una de las siguientes:

- `acerca-de-isc-projects`: Para información institucional o general del proyecto.
- `guías-tecnicas`: Para procedimientos técnicos, tutoriales o guías prácticas.
- `documentacio-apis`: Documentación relacionada a APIs utilizadas o desarrolladas.
- `manuales`: Instrucciones de uso o manuales funcionales.

Si pertenece ponla en una de estas.
