# Checklist de Validación para Spikes

Antes de aprobar o cerrar un Spike, se recomienda asegurarse que cumple con los siguientes criterios para garantizar su utilidad y enfoque técnico.

---

## Claridad y Propósito

- [ ] ¿El Spike presenta una duda o problema técnico específico?
- [ ] ¿Se justifica su existencia como una investigación previa a una funcionalidad?

---

## Objetivo y Alcance

- [ ] ¿Tiene un objetivo claro y alcanzable?
- [ ] ¿Se definió correctamente el límite de tiempo (timebox)?

---

## Entregables y Documentación

- [ ] ¿Incluye entregables claros (documento, decisión, código de prueba)?
- [ ] ¿El resultado o hallazgo fue documentado y compartido?

---

## Exclusión de Implementación

- [ ] ¿Se evitó incluir código funcional definitivo o desarrollo de producción?
- [ ] ¿El equipo entendió que el Spike no es una User Story?

---

## Conclusión

- [ ] ¿Se llegó a una conclusión o aprendizaje útil para el equipo?
- [ ] ¿La documentación es reutilizable para futuras decisiones?
