# Referencias Utilizadas

A continuación se listan las fuentes consultadas para la elaboración de esta guía sobre comentarios en Pull Requests (PR). Todas las referencias son oficiales, accesibles y confiables, orientadas a mejorar las prácticas de revisión colaborativa de código.

---

## Artículos y Guías Oficiales

- **GitHub – Reviewing proposed changes in a pull request**  
  https://docs.github.com/en/pull-requests/collaborating-with-pull-requests/reviewing-changes-in-pull-requests  
  Guía oficial de GitHub sobre cómo revisar y comentar PRs correctamente, con enfoque colaborativo.

- **Atlassian – 5 code review best practices**  
  https://www.atlassian.com/blog/add-ons/code-review-best-practices  
  Buenas prácticas sobre cómo revisar código, con énfasis en claridad, respeto y efectividad en los comentarios.

- **Google Engineering Practices – Code Review Developer Guide**  
  https://google.github.io/eng-practices/review/reviewer/comments.html  
  Detalle de cómo hacer comentarios útiles y productivos en una revisión de código, parte de la guía oficial de prácticas de ingeniería de Google.

- **Stack Overflow Blog – How to Make Good Code Reviews Better**  
  https://stackoverflow.blog/2019/09/30/how-to-make-good-code-reviews-better/  
  Consejos prácticos y errores comunes al hacer comentarios en PRs.
  
---

## Recomendaciones de búsqueda

Si alguna fuente no está disponible directamente, se recomienda buscar los siguientes términos:

- `"how to review pull requests"`  
- `"constructive code review comments"`  
- `"best practices for commenting PRs"`

---

## Aplicación

Estas referencias fueron utilizadas para:

- Establecer buenas prácticas de comunicación en Pull Requests.
- Definir frases útiles y comentarios frecuentes.
- Construir el checklist de revisión desde una base validada por la industria.
